vwFactory 更新日志
==================

未发布
  - 修复: 对话里图片较多时 (例如连续读取十几张截图)，请求报 413 "Request Entity Too Large"，
    之后连 /compact 也报同样的错，对话无法继续。Factory 网关的请求体上限约 4.5 MB
    (实测 4.25 MiB 可以，4.5 MiB 返回 413)，而 DSH 默认允许一次请求带 20 MiB 的图片，
    自动压缩又只看 token 数、不看图片字节数。现在 Factory 的各个分组限制图片总量 3 MiB、
    单张 512 KiB；超出时 DSH 会把最早的图片换成「附件 id + 本地路径」的文字，模型需要时可以重新读取。
    已安装的用户: 更新后重启 DSH，插件会自动把这两项写进配置，再重启一次即生效
  - Grok 在模型选择里单独显示为「Factory (Grok)」分组 (仍走 /responses)，不再混在 Factory (GPT) 里

v0.4.11 (测试版)
  - 修复: 在新版 DeepSeek Harness 上安装后 DSH 无法启动 (报 cordis.patch.yml 第 20 行 "[]" 出错)。
    新版 DSH 的默认配置文件以 "[]" 结尾，安装脚本追加配置时没有去掉它，导致文件格式错误。
    已经出错的，重新运行本版 install.bat 即可自动修好；卸载时也会正确恢复 "[]"

v0.4.10 (测试版)
  - Gumloop 省积分: Claude 的上下文缓存有效期从 5 分钟延长到 1 小时。以前离开超过 5 分钟再回来，
    长对话要把整段上下文重新写入缓存 (15 万 token 约 150 积分)；现在 1 小时内回来仍然命中缓存。
    实测 Gumloop 对 1 小时缓存按普通缓存写入价计费，不额外收费

v0.4.9 (测试版)
  - 新增: Gumloop 账号接入。设置 → Factory 账号 → Gumloop → 添加，填 Gumloop 的 API Key 和 User ID
    (Gumloop 网页 → 设置 → Connectors → Gumloop API Key 页面)。添加后重启 DSH，模型选择里出现「Gumloop」分组
  - 余额: Gumloop 的 API 不提供余额查询，插件按官方价格逐笔计算每次调用的花费 (含缓存读写，
    每次调用向上取整到 1 积分，与 Gumloop 实际扣费规则一致)，从你「校准」时填的网页剩余积分里扣减。
    选中 Gumloop 模型时，输入框下方的胶囊显示 Gumloop 剩余积分；网页端任务的花费要重新校准才会反映
  - 多个 Gumloop 账号: 当前账号积分用完时自动换下一个账号重发；Gumloop 与 Factory 账号互不混用
  - 提示: Gumloop 按官方原价计费，长对话第一轮要把整段上下文写入缓存，花费明显高于后续轮次
  - 已知问题 (Gumloop 自身): DeepSeek V4.1 Flash、MiniMax M3、Kimi K2.7 Code、DeepSeek V4 Pro 目前在 Gumloop 上调用会报错

v0.4.8
  - 新增: Gemini (3.1 Pro / 3.8 / 3.7 / 3.6 / 3.5 / 3 Flash) 与 Grok (4.7 / 4.6 / 4.5) 模型，
    更新后重启 DSH，检测通过的模型会自动出现在模型列表 (Gemini 在「Factory」，Grok 在「Factory (GPT)」)。
    感谢 @CJMECOLEM 的 PR #1
  - Gemini 可以连续调用工具: Gemini 每次调用工具都会返回一个签名，下一轮必须带回去，否则报 400；
    插件现在会记住签名并自动补回 (找不到时用官方的跳过值)
  - Gemini 支持图片输入；思考档位为 低 / 中 / 高 (Gemini 3 无法关闭思考，因此不提供「关闭」)；
    Grok 思考档位为 低 / 中 / 高 / 超高

v0.4.7
  - 修复: 通过 Factory 通道使用 Claude 时，中文 / emoji 偶发显示为乱码 (多字节字符被拆在两个网络包之间)，
    并兼容 CRLF 换行和末尾没有空行的事件
  - 修复: 上游中途断开时可能导致插件进程异常 (未处理的流错误) 或 DSH 一直卡在「生成中」，
    现在会立刻收到错误提示并正常结束；Claude 流里的 error 事件也会正确显示
  - 超时保护: 流式请求 120 秒内上游无响应、或输出中途 150 秒没有任何数据，自动中止并报错
    (可用环境变量 VWFACTORY_FIRST_BYTE_TIMEOUT_MS / VWFACTORY_IDLE_TIMEOUT_MS 调整，0 = 关闭)
  - 临时故障自动重试: 遇到 500/502/503/504/529 或网络错误，先在同一账号退避重试 2 次 (约 1 秒、3 秒)，
    仍失败再临时借用另一个账号一次；这类错误不让账号进入冷却，也不改变当前账号
  - 在对话里点停止后，同时取消上游请求，不再在后台继续消耗额度
  - 启动更快: Key 解密改为后台进行，不再卡住 DSH 主进程 (原来每次启动卡 0.3~2 秒)
  - 设置页改版，更清爽:
      * 额度圈加上灰色底圈作参照，一眼看出用了多少
      * 默认只显示主额度，副额度用账号右上角的「主额度 / 副额度」开关切换 (会记住选择)
      * 账号放到最上面；非当前账号默认折叠成一行 (5h / 周 / 月)，点击展开
      * 刷新 / 复制 Key / 删除收进「⋯」菜单；回滚、下载页、可用模型、浏览器打开也都收进「⋯」
      * 去掉各处小字说明 (悬停仍可查看)；重置时间改为悬停额度圈查看
      * 「刷新额度」改为 ↻ 图标；折叠的账号只显示用得最多的那一项，悬停看全部
      * 均衡模式下不再显示「使用中 / 切换」(该模式不按当前账号分配)，改为显示每个账号的对话数
      * 「使用中」标签改为账号名旁的绿色小圆点

v0.4.4

      * 旧版本自动备份，出问题可一键「回滚」
      * 更新后完全退出并重新打开 DSH 生效
      * 需要重新运行安装程序的版本会提示去下载页
  - 注意: 从 v0.4.3 及更早版本升级到 v0.4.4 需要手动安装一次，之后就能在线更新

v0.4.3
  - Key 加密保存: secrets.json 改用 Windows DPAPI 按当前用户加密，只有你的 Windows 账户能解开
      * 旧的明文文件首次启动自动迁移，备份 (*.bak) 一并加密，数据目录里不再有明文 key
      * 解不开时 (换电脑 / 换用户) 原文件原样保留，不会被覆盖；设置页提示
      * 系统禁止加密时退回明文保存并提示，不会丢 key；VWFACTORY_PLAIN_SECRETS=1 可关闭加密
  - 设置页显示「Key 已加密」

      * 开源模型按实测声明: glm-5.3-flash、kimi-k3、DeepSeek V4 系列、minimax-m3、minimax-m2.7 支持；

v0.4.1
  - 数据文件改为安全写入 (先写临时文件再替换)：账号、key、本机令牌、cordis.patch.yml
    写到一半崩溃或断电也不会损坏 (实测强杀 40 次: 旧写法损坏 2 次，新写法 0 次)
  - 自动备份: key 文件每次保存前备份，账号文件启动时及每 10 分钟备份 (*.bak)
  - 自动恢复: 文件损坏或丢失时从备份恢复，损坏的文件另存为 *.corrupt-时间 不会被覆盖，
    设置页会显示提示

v0.4.0
  - 多账号均衡 (设置 -> Factory 账号 -> 分配方式，默认仍是「单账号」):
      * 每个对话固定在一个账号上 (按会话指纹识别)，保证缓存命中；空闲 60 分钟后释放
      * 新对话分给主额度剩余最多的账号 (同时考虑进行中的请求和对话数)
      * 账号主额度到 90% 或出错冷却时，对话在下一轮自动迁到更健康的账号；
        所有账号都 >=90% 时不来回切换
      * 出错换号只改变该对话的账号，不影响其它对话
  - 额度提醒: 主额度到 75% / 90% / 用完时各提醒一次，恢复后提示；自动切号也会提示
  - 使用期间后台每 5 分钟刷新额度 (提醒和均衡都依赖它)，请求后也会顺带刷新
  - 输入框胶囊 / 弹窗 / 设置页显示分配方式、各账号对话数和冷却状态
v0.3.0
  - 客户端版本号更新到 0.238.0，并会自动跟随 Factory 官方最新版本 (每 6 小时检查，只升不降)
  - 同一对话使用固定的会话 ID (之前每个请求随机)，与官方 Droid 行为一致，利于服务端缓存与会话亲和；
    GPT (Responses) 请求自动带上 prompt_cache_key
  - Claude 5.x 直接发送 adaptive 思考参数，不再先报 400 再重试；修正思考预算到强度的映射
  - 自动切号增强:
      * 出错时依次尝试所有账号 (之前只试一个)
      * 出错账号进入冷却: 401/403 冷却 30 分钟，402 冷却 6 小时，
        429 冷却到对应额度窗口重置 (未知时按 Retry-After，30 秒~30 分钟)
      * 请求前若当前账号在冷却中或标准额度已用满，先切到可用账号
  - 额度显示更稳: 窗口重置后自动归零；兼容 secondsRemaining / notAvailable；
    查询失败时保留上次数据
  - Anthropic 请求在客户端未设置时自动加缓存标记 (DSH 自身已会加，主要惠及外部客户端)
